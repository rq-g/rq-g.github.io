面向对象之多态——同一接口，多种实现

发布于 2022-01-08 分类：技术, 2022, Java基础 👁

前言

刚学多态的时候觉得概念很虚：父类引用指向子类对象，这有什么用？直到在项目里用策略模式替换了一坨 200 多行的 if-else 支付分支，又用同一套思路重构了矿卡调度的消息处理器，才真正体会到：多态不是语法特性，是解耦工具。

这篇文章从”为什么”讲到”怎么落地”，最后下探到 JVM 层面看看动态绑定到底是怎么发生的。

什么是多态？

多态的字面意思是”多种形态”。在 Java 中，多态是指父类引用指向子类对象，调用同一个方法，表现出不同的行为。

同一个 animal.speak() 调用，因为实际对象不同，产生了不同的行为——这就是多态。

多态的三个前提条件

  1. 有继承关系（或实现关系）
  2. 有方法重写（Override）
  3. 父类引用指向子类对象

三个条件缺一不可。第三条最容易忽视——Dog dog = new Dog(); dog.speak(); 这不是多态，这是普通调用。

多态的本质：动态绑定

多态的底层机制是动态绑定（运行时多态）。理解它需要分清”编译时”和”运行时”两个视角：

  • 编译时：看引用类型（父类），决定”能调用哪些方法”——父类没有的方法，编译直接报错
  • 运行时：看实际对象类型（子类），决定”执行谁的代码”——JVM 根据对象头里的实际类型找到重写后的方法

JVM 是怎么找到那个方法的？

方法的调用在字节码层面有不同指令：

指令 适用方法 绑定时机
invokestatic 静态方法 编译期静态绑定
invokespecial 构造器、private 方法、super 调用 编译期静态绑定
invokevirtual 普通实例方法 运行期动态绑定
invokeinterface 接口方法 运行期动态绑定

动态绑定的实现依赖 虚方法表（vtable）：每个类在方法区有一张表，指向自己实际生效的方法入口。子类重写了方法，就把表项替换成自己的实现；子类没重写，就沿用父类的表项。调用时只需两步：拿到对象实际类型 → 查它的 vtable → 跳转。所以动态绑定几乎没有性能开销，不必为性能顾虑放弃多态。

多态的三个经典陷阱

陷阱 1：属性没有多态

属性访问在编译期就按引用类型解析（字段没有虚方法表），所以看到的是 Parent 的 name。这是”字段遮蔽”（field hiding）——子类的 name 只是隐藏了父类的，不是重写。

实践准则：父类字段一律 private，暴露 getter/setter。这样访问者只能走方法，方法是有多态的。

陷阱 2：静态方法没有多态

子类的同名静态方法只是隐藏（hiding）了父类方法，不构成重写。字节码层面 obj.hello() 实际编译成 invokestatic Parent.hello()——按编译类型调用。所以静态方法永远用类名调用，别用实例调用，能避免 90% 的困惑。

陷阱 3：private / final 方法没有多态

private 方法对子类不可见，final 方法禁止重写——它们在编译期就确定了调用目标，走的是 invokespecial / 静态绑定路径。

一个隐蔽的变体：父类的 public 方法在子类里被写成了 private，编译不报错（因为不是重写，是另一个方法），但多态会静默失效。重写方法的访问权限只能放大不能缩小，遵守这条规则可以避开这个坑。

向上转型与向下转型

类型 方向 说明 安全性
向上转型 子 → 父 隐式自动完成 绝对安全（子类 capabilities ⊇ 父类）
向下转型 父 → 子 必须显式强转 不安全，类型不符抛 ClassCastException

但要警惕：代码里大量 instanceof + 向下转型，是多态设计失败的信号。既然用了 Animal 引用，说明调用方不想关心具体类型；又要 instanceof 强转回子类，等于绕回了 if-else 老路。正确做法是把”特有操作”上提为接口方法，或者用访问者模式处理异质集合。

多态的框架级应用：SPI

多态不止用于业务代码，它还是整个 Java 生态的扩展基石。SPI（Service Provider Interface） 就是典型：

DriverManager 怎么知道有哪些数据库驱动？答案是读各驱动 jar 包里的 META-INF/services/java.sql.Driver 文件——每个驱动把自己的实现类注册进去，运行时动态加载。调用方写的是接口，实现方注入的是实现，这正是多态在框架层面的表达。Spring 的自动装配、Dubbo 的 SPI 扩展点、SLF4J 的日志门面，都是同一套思想。

总结

  1. 多态的三个前提：继承/实现 + 重写 + 父类引用指向子类对象，缺一不可；
  2. 本质是 invokevirtual / invokeinterface 的运行期动态绑定，由虚方法表实现，几乎零开销；
  3. 属性、静态方法、private/final 方法都没有多态——记住”字段看编译类型，方法看实际类型”这句口诀；
  4. 落地抓手是策略模式 + Spring 注入集合自建工厂，凡是”按类型路由到不同处理逻辑”的场景都适用；
  5. SPI 是多态的框架级表达：面向接口编程 + 运行时注入实现，JDBC、Spring、Dubbo 都靠它扩展；
  6. 最后一句检验标准：代码里出现成片的 instanceof 强转或按类型分支的 if-else，就是该用多态重构的信号。
