前言

HashMap是Java中使用频率最高的集合之一，也是面试的”常驻嘉宾”。深入理解HashMap源码从”只会用put/get”到理解底层原理，这个过程让我对数据结构有了全新的认识。

在实际场景中，HashMap无处不在：设备信息缓存、告警分组统计、配置参数映射。理解HashMap的底层原理，不仅能通过面试，更能写出高性能的生产代码。

HashMap核心数据结构

JDK1.7：数组 + 链表

0 → null
1 → Node → Node → Node (链表)
2 → null

JDK1.8：数组 + 链表 + 红黑树

0 → null
1 → Node → Node → … → TreeNode (链表长度>=8转红黑树)
2 → null
3 → TreeNode (红黑树，查找O(logn))
4 → Node → Node

高级面试题补充

Q1: JDK8中HashMap的resize做了哪些优化？

  1. 重新定位优化：不需要重新计算hash，只看hash的新增位
  2. 尾插法：JDK7用头插法，并发扩容时可能形成环形链表；JDK8改用尾插法

Q2: HashMap是如何查找元素的？

  1. 根据key的hashCode计算hash值
  2. 根据hash值定位数组下标：(n-1) & hash
  3. 比较Node的key是否相等（==或equals）
  4. 红黑树O(logn) / 链表O(n)

HashMap容量与性能关系

HashMap容量与性能关系分析

  • 容量太小：
  • 频繁扩容，大量数组拷贝
  • hash碰撞概率高，链表/红黑树多
  • get/put性能下降
  • 容量太大：
  • 内存浪费，大量空桶
  • 遍历效率低
  • 初始化耗时增加
  • 容量合适（负载因子0.75）：
  • hash碰撞概率低
  • 扩容次数少
  • 内存利用率合理
  • 容量计算公式：
  • capacity = (int)(expectedSize / 0.75) + 1
  • 例如：预期3000台设备
  • capacity = (int)(3000 / 0.75) + 1 = 4001
  • 取最接近的2的幂：4096
