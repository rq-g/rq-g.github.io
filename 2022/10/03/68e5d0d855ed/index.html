字符串深入——那些你不知道的坑

发布于 2022-10-03 分类：技术, 2022, Java基础 👁

前言

String 是 Java 中使用最频繁的类，也是最容易被”想当然”的类。== 比较、循环拼接 O(n²)、new String("x") 创建几个对象——面试常客，但真正把它们讲透、并且知道为什么的人不多。这篇文章从不可变性设计出发，把常量池、拼接演进、经典坑一次讲清。

不可变性：为什么 String 要设计成不可变？

三层防御：final 类不可被继承重写（防止子类破坏不变性）、value 数组 final 引用不可换、String 类不提供任何修改 value 的方法。

不可变带来的四个好处

好处 原理
线程安全 状态不可变，天然线程安全，随便共享
常量池可行 内容不变才能全局共享同一对象，否则一个引用改了值全炸
hashCode 缓存 hash 只算一次存在 hash 字段——String 是 HashMap 最常用的 key，每次 get 免去重算，这是 HashMap 性能的隐形功臣
安全性 文件路径、数据库连接串、类加载器加载的类名，如果字符串可变，一处恶意修改就能越权

JDK 9 的 compact strings：一个隐藏的内存优化

JDK 8 的 char[] 是 UTF-16，每个字符固定 2 字节——但绝大多数字符串是纯 ASCII。JDK 9 改为 byte[] + coder 标志：纯 Latin-1 字符串每字符只占 1 字节，包含中文等 BMP 字符时才用 2 字节。纯英文的字符串场景（JSON 报文、URL、日志），内存直接省一半。

常量池的位置随版本变过，这直接解释了 intern() 的行为差异：

JDK 常量池位置 intern 行为
6 永久代（PermGen，大小固定易 OOM） 首次遇到就复制到常量池
7+ 堆 首次遇到只存堆上对象的引用，不复制

经典面试题 new String("hello") 创建几个对象？标准答案：1 或 2——“hello” 字面量如果常量池没有，先创建常量池对象（1 个）；new 必然在堆上再创建一个（1 个）。所以是”至少 1 个，最多 2 个”。

== vs equals 与编译期优化

字符串比较铁律：永远 equals，判空用 Objects.equals(a, b)。

结论：字面量 + 字面量、final 变量参与拼接，编译期折叠进常量池；运行期变量拼接产生新对象。所以永远不要用 == 判等——它恰好”对”的时候（true）反而害你最深的，因为你会以为它可靠。

拼接的底层演进

  • JDK 8：+ 编译成 StringBuilder.append()（循环里用 + 不会优化——编译器在循环内 new StringBuilder，每轮一个，O(n²) 照旧）；
  • JDK 9+：+ 编译成 invokedynamic + StringConcatFactory，运行时按参数个数和类型选最优策略（甚至 Arrays.copyOf 一次分配），性能大幅优于 JDK 8。

即便如此，循环里显式 StringBuilder 仍然是正解——语义清晰、各版本行为一致。

StringBuilder vs StringBuffer

StringBuffer “线程安全”是伪需求：拼接通常是方法内局部变量，天然无线程竞争；真有共享拼接需求，正确姿势是外部加锁或并发方案，而不是一个粒度极细的 synchronized（它保证不了”先 append A 后 append B”的原子序列）。

容量预估：一次扩容都不发生

大字符串场景（报表生成、SQL 拼接），预估容量能省掉十几轮整组拷贝。

1. substring 内存泄漏（JDK 6 古董坑，面试还在问）

2. switch 字符串：null 会 NPE

3. split 是正则：. 和 | 是特殊字符

4. 编码问题：永远显式指定

跨系统传输、文件读写出现乱码，九成是某个环节用了平台默认编码。

5. 判空三层次

isEmpty 与 isBlank 的区别在真实业务里是坑：表单输入 “ “（全空格）时 isEmpty 放行，isBlank 拦截——用错一个就是脏数据入库。

总结

  1. 不可变性是 String 一切特性的地基：线程安全、常量池共享、hashCode 缓存、安全性——理解了”为什么不可变”，常量池和 == 陷阱就都顺理成章；
  2. 常量池 JDK 7 起在堆上，intern() 从”复制”变”存引用”，new String("x") 创建 1~2 个对象；字面量拼接编译期折叠、final 变量折叠、变量拼接新对象——但永远用 equals，别赌 ==；
  3. 循环拼接 O(n²) 的账要会算；+ 在 JDK 9+ 有 invokedynamic 优化，但循环里仍显式 StringBuilder，并预估容量避免反复扩容；
  4. 实战坑清单：split 是正则（.、| 要转义、尾部空串默认丢弃）、switch 遇 null 抛 NPE、编码永远显式 UTF-8、isEmpty 和 isBlank 语义不同；
  5. 工具类选择：判空 StringUtils.isBlank、集合转串 String.join、格式化热路径用 StringBuilder 而非 format；
  6. 三条铁律覆盖 90% 的坑：equals 比较、循环用 StringBuilder、判空用 isBlank——但理解了原理，你还能预判那剩下的 10%。
