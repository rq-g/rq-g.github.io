HashSet与LinkedHashSet——去重与顺序的抉择

发布于 2022-02-06 分类：技术, 2022, Java基础 👁

前言

刚做实际项目的时候，有个需求是对一批传感器设备编号去重。我直接用了HashSet，功能没问题，但测试同学反馈”安全巡检列表的顺序和原始顺序不一样”。当时我还觉得奇怪——去重就完事了，谁管顺序？后来才明白，业务场景对顺序的要求远比我想象的多。

HashSet：无序去重

HashSet基于HashMap实现，底层就是HashMap的key：

HashSet 底层存储结构

  • HashSet
  • HashMap<E, Object>
    • key = 元素值
    • value = PRESENT（固定空对象）
  • HashMap内部：
  • | null | D002 | null | D001 | null | D003 | null | null |
  • 遍历顺序：D002, D001, D003（不确定）
  • 与插入顺序 D001, D002, D003 不同

核心特点：

  • 不允许重复：通过equals和hashCode判断
  • 无序：遍历顺序和插入顺序无关
  • 允许null：最多一个null元素
  • 线程不安全

去重原理

踩坑：不重写hashCode

原因：不同对象的hashCode大概率不同，会被分配到不同的桶位，equals根本不会被调用。

LinkedHashSet：有序去重

LinkedHashSet是HashSet的子类，底层使用LinkedHashMap：

核心区别：维护了一个双向链表记录插入顺序

LinkedHashSet 底层存储结构

  • LinkedHashSet
  • LinkedHashMap<E, Object>
    • HashMap结构（桶+链表/红黑树）
    • 双向链表（记录插入顺序）
  • HashMap部分：
  • [0]null [1]D001 [2]null [3]D002 …
  • 双向链表部分：
  • head → D001 ⇄ D002 ⇄ D003 ← tail
  • （按插入顺序连接）
  • 遍历顺序：D001, D002, D003（确定，等于插入顺序）

性能对比

操作 HashSet LinkedHashSet 差异
添加 O(1) O(1) 相当
删除 O(1) O(1) 相当
查找 O(1) O(1) 相当
遍历 略快 略慢（维护链表） 可忽略
内存 较少 较多（链表指针） 可忽略

实际差距很小，日常开发中基本可以忽略。

TreeSet：排序去重

顺便提一下TreeSet，它是基于红黑树的有序集合：

特点：

  • 排序去重：按自然顺序或自定义顺序排列
  • 不允许null：排序需要比较，null无法比较
  • 性能：增删查O(log n)，比HashSet慢

三种Set对比：

三种 Set 实现对比

  • HashSet LinkedHashSet TreeSet
  • 无序 ├── 插入顺序 ├── 排序
  • O(1)增删查 ├── O(1)增删查 ├── O(logn)增删查
  • 允许null ├── 允许null ├── 不允许null
  • 最快 └── 略慢 └── 最慢
  • 选择指南：
  • 只需要去重 → HashSet
  • 去重+保序 → LinkedHashSet
  • 去重+排序 → TreeSet

如何选择？

面试常见问题

Q1: HashSet如何保证元素唯一性？

通过hashCode和equals双重判断：先比较hashCode定位桶，再比较equals判断内容。只有hashCode相同且equals为true才认为是重复。

Q2: 为什么equals和hashCode必须一起重写？

如果只重写equals不重写hashCode，两个equals相等的对象可能被分到不同的桶，equals根本不会被调用，导致去重失败。

Q3: HashSet的初始容量怎么算？

与HashMap相同，公式：capacity = (int)(expectedSize / 0.75) + 1

Q4: HashSet是线程安全的吗？

不是。多线程环境下可以使用ConcurrentHashMap.newKeySet()或Collections.synchronizedSet()。

总结

对Set集合的认知从”去重工具”升级为”根据场景选择合适的实现”。HashSet无序高效，LinkedHashSet有序略慢，TreeSet排序最慢。大多数业务场景用LinkedHashSet最省心——既去重又保序，性能差距可以忽略不计。实际场景中，设备去重保序用LinkedHashSet，设备类型判断用HashSet，安全评分排序用TreeSet。记住一点：自定义对象放进Set，equals和hashCode必须一起重写！

为什么只重写equals不够？

只重写equals的问题

  • Step 1: add(device1)
  • hashCode() → 12345 → 桶位 5
  • 桶5为空 → 插入成功
  • Step 2: add(device2) [和device1 equals相等]
  • hashCode() → 67890 → 桶位 10 ← 不同的hashCode！
  • 桶10为空 → 插入成功
  • 结果：Set中有两个equals相等的对象！
  • 原因：不同hashCode导致分到不同桶，equals根本没被调用
