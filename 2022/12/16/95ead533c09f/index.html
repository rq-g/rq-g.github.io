SQL注入防范——安全编码的第一道防线

发布于 2022-12-16 分类：技术, 2022, 安全 👁

前言

SQL 注入排在 OWASP Top 10 的注入类攻击第一位，也是最”古老”却至今仍在发生的漏洞。它危险在哪？一条拼接的 SQL，轻则泄露全表数据，重则 DROP TABLE、提权、拖库。

很多人对 SQL 注入的理解停留在”知道有这回事”，但写代码的时候还是会在 MyBatis 里随手一个 ${}。这篇文章从注入原理讲到 MyBatis 的 #{} 与 ${} 底层区别，再讲到 LIKE、IN、动态排序这些”看似必须用 ${}“的场景怎么安全处理，最后给出一份可以直接抄进团队的速查清单。

核心认知先放这里：永远不要信任用户输入，永远用预编译参数。#{} 代替 ${}、白名单校验、参数校验——这三条规则能防范 90% 的注入攻击；剩下 10% 靠纵深防御（最小权限账号 + 安全扫描 + 日志审计）。

什么是SQL注入？

SQL 注入的本质只有一句话：用户输入被当成了 SQL 代码来执行。SQL 里最常见的字符串拼接，恰好就是”代码和数据”的分界线被抹掉的过程。

MyBatis中的SQL注入

Java 项目大部分注入漏洞不在 JDBC 拼接（很少直接写了），而在 MyBatis 的 ${} 使用不当。

#{} vs ${}：底层区别才是关键

两者不是”写法习惯”问题，而是走了完全不同的 SQL 执行路径：

维度 #{} ${}
处理方式 预编译占位符 ?，参数后绑定 文本替换后整体编译
是否走 SQL 解析器 参数不参与解析 参数参与解析
性能 同一 SQL 可复用执行计划 每次文本不同，无法复用
注入风险 无 有
适用场景 一切”值” 表名/列名等”结构”（需白名单）

一个必须理解的点：预编译之所以能防注入，不是因为”转义了特殊字符”，而是因为参数值从头到尾不进入 SQL 语法解析阶段。哪怕参数里带 ' OR '1'='1，它也只是 ? 位置上的一个普通字符串值。

${}的”合法”使用场景

#{} 只能绑定值，不能改变 SQL 结构。但有些场景偏偏要动态改变结构：

场景 能否用#{} 原因
WHERE 条件的值 ✅ 必须 标准参数绑定
ORDER BY 列名 ❌ ORDER BY ? 只会把列名当成字符串常量，排序失效
动态表名（分表） ❌ FROM ? 语法不合法
动态排序方向 ASC/DESC ❌ 同上，会被当常量

也就是说：${} 不是禁用，而是必须收口到白名单。

${}的安全处理：白名单是唯一正解

为什么用”映射回白名单值”而不是”正则校验用户输入”？因为黑名单/正则总能被绕过（大小写、编码、注释符变体），而白名单是”不在这个列表里一律拒绝”，没有绕过空间。

顺带两个工程实践要点：

  1. 预编译还能提速：同一条 SQL 反复执行时（高频查询），执行计划可以复用，这就是”绑定变量”在高并发下的隐藏收益。
  2. MyBatis-Plus / JPA 同理：QueryWrapper 的 eq("name", input) 底层就是 #{}；但 apply("name = '" + input + "'") 这种写法又回到了拼接，等于白瞎了框架。

XSS防范：注入的近亲

XSS 和 SQL 注入是同一个思想的两面：把数据当成了代码（SQL 注入是输入进了 SQL 解析器，XSS 是输入进了 HTML/JS 解析器）。

全局XSS过滤器

两个工程提醒：

  1. 正则黑名单过滤 XSS 和防 SQL 注入一样不可靠，富文本场景请上 OWASP Java HTML Sanitizer 或 jsoup 的 Safelist。
  2. 过滤器是全局的，会影响所有接口的入参——对需要接收富文本 HTML 的接口（如公告编辑）要做路径白名单豁免，否则运营发的文章会被转义成一堆 &lt;p&gt;。

总结

SQL 注入防范体系可以压缩成一张决策图：

flowchart TD
    A[用户输入进入 SQL] --> B{是什么角色?}
    B -->|值| C[#{} 预编译参数]
    B -->|结构: 表名/列名/排序| D[白名单校验后 ${}]
    B -->|LIKE 模糊值| E[CONCAT + #{} + 通配符转义]
    B -->|IN 集合| F[foreach + #{}]
    C --> G[纵深防御]
    D --> G
    E --> G
    F --> G
    G --> G1[最小权限数据库账号]
    G --> G2[参数校验 + XSS 过滤]
    G --> G3[安全扫描 + 注入 payload 单测]

记住三句话：

  1. #{} 是默认，${} 是例外——每个 ${} 出现的地方，必须能指到一段白名单校验代码；
  2. 白名单优于正则校验，类型绑定优于字符串处理；
  3. 防注入不是单点，预编译 + 最小权限 + 扫描测试三层叠加，任何一层失守还有下一层。
