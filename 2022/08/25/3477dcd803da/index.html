SpringBoot定时任务——从cron到线程池

发布于 2022-08-25 分类：技术, 2022, SpringBoot 👁

前言

实际场景中，定时任务无处不在：每天凌晨同步矿工考勤数据、每5分钟检查瓦斯超限报警、每小时统计各矿井产量、每10秒刷新井下人员定位缓存。最初我用Spring的@Scheduled注解，简单好用，但后来发现单线程执行定时任务有坑——瓦斯报警检查任务卡住，人员定位刷新任务就等着，这在矿山安全场景下是不可接受的。

线程池大小选择指南

  1. CPU密集型任务：线程数 = CPU核数 + 1
  2. IO密集型任务：线程数 = CPU核数 * 2
  3. 混合型任务：根据实际监控调整
  4. 矿山场景：IO密集为主（数据库/Redis/设备通信）

定时任务的注意事项

1. 任务执行时间超过间隔

2. 应用重启时任务重复执行

3. 分布式锁防止重复执行

4. 分布式锁优化：Redisson

定时任务 vs 消息队列 vs 延时任务

特性 @Scheduled 延迟消息(RocketMQ) 延时任务(XXL-JOB)
精确度 分钟级 秒级 秒级
实时性 轮询，有延迟 事件驱动，精准 轮询+回调
资源消耗 定时扫描 按需触发 调度中心管理
分布式 需自己加锁 天然支持 天然支持
动态配置 需SchedulingConfigurer 发消息即可 管理后台配置
适用场景 批量处理、统计报表 超时取消、延迟通知 复杂调度、可视化管理
复杂度 低 中 高

定时任务方案选型

  • 需求是什么？
  • |
  • +– 固定时间执行统计/同步 → @Scheduled + 分布式锁
  • |
  • +– 某事件后延迟执行 → 延迟消息（RocketMQ延时消息）
  • | 例：下单30分钟未支付自动取消
  • |
  • +– 复杂调度需求 → XXL-JOB
  • | 例：需要可视化管理、手动触发、失败重试、分片执行
  • |
  • +– 矿山安全场景 → @Scheduled + Redisson锁 + 报警
  • 例：瓦斯检测、设备心跳、人员定位

XXL-JOB简介

XXL-JOB vs @Scheduled

特性 @Scheduled XXL-JOB
调度管理 代码中硬编码 管理后台可视化配置
动态调整 需重启应用 实时生效
失败重试 需自己实现 内置重试策略
任务监控 需自己实现 内置执行日志
分片执行 不支持 支持
手动触发 不支持 支持
分布式 需加锁 内置分片+故障转移
报警通知 需自己实现 内置邮件/钉钉通知
适用规模 < 30个任务 无限制
