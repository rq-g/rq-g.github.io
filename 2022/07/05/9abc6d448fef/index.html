MySQL多表查询——联表查询与子查询

发布于 2022-07-05 分类：技术, 2022, MySQL 👁

前言

实际场景中，矿工信息分布在多张表中：矿工基本信息、考勤记录、薪资记录、设备使用记录等。单表查询无法满足业务需求，必须用联表查询或子查询来组合数据。刚接手项目时，JOIN和子查询傻傻分不清，经常写出效率极低的查询，导致矿工考勤报表查询耗时超过10秒。后来系统学习了多表查询，才掌握了正确的姿势。

本文将结合实际项目的实战场景，深入讲解JOIN类型、执行原理、子查询、多表查询优化等核心知识。

JOIN的执行原理

Nested Loop Join（嵌套循环）

MySQL默认的JOIN算法：

  • Simple Nested Loop Join（简单嵌套循环）
  • ================================
  • for (row1 in left_table) { – 驱动表（外表）
  • for (row2 in right_table) { – 被驱动表（内表）
  • if (row1.key == row2.key) {
  • output(row1, row2);
  • }
  • }
  • }
  • 复杂度：O(M * N)，M=左表行数，N=右表行数
  • 效率极低！每行左表都要全表扫描右表
  • Index Nested Loop Join（索引嵌套循环）
  • ======================================
  • for (row1 in left_table) { – 驱动表
  • // 被驱动表有索引，走B+树查找
  • row2 = right_table.indexLookup(row1.key);
  • if (row2 found) {
  • output(row1, row2);
  • }
  • }
  • 复杂度：O(M * logN)，被驱动表走索引
  • 效率大幅提升！这是最常见的优化手段
  • Block Nested Loop Join（块嵌套循环）
  • ========================================
  • – 被驱动表没有索引时使用
  • – 将驱动表的数据加载到join_buffer中
  • – 然后扫描被驱动表，与join_buffer做匹配
  • join_buffer = loadBatch(left_table);
  • for (row2 in right_table) {
  • for (row1 in join_buffer) {
  • if (match(row1, row2)) output(row1, row2);
  • }
  • }
  • 优化：增大join_buffer_size可减少扫描次数
  • SET join_buffer_size = 8388608; – 8MB

小表驱动大表

小表驱动大表原理：

  • 大表驱动小表：
  • 外层循环100万次，每次查内表索引
  • 总开销 = 100万 * (查索引成本)
  • 小表驱动大表：
  • 外层循环5000次，每次查内表索引
  • 总开销 = 5000 * (查索引成本)
  • 结论：外层循环次数越少越好 → 小表做驱动表

EXISTS子查询

EXISTS vs IN 选择策略：

  • 子查询结果集小 → 用 IN
  • ===========================
  • – 安全隐患表只有50条PENDING记录
  • SELECT * FROM mine_dept
  • WHERE id IN (SELECT dept_id FROM safety_hazard
  • WHERE status = ‘PENDING’);
  • – 先查50条记录，再在mine_dept中匹配
  • 外表小 → 用 EXISTS
  • =======================
  • – mine_dept只有10个部门
  • SELECT d.dept_name FROM mine_dept d
  • WHERE EXISTS (SELECT 1 FROM safety_hazard h
  • WHERE h.dept_id = d.id
  • AND h.status = ‘PENDING’);
  • – 只需执行10次子查询

子查询 vs JOIN

子查询 vs JOIN 性能对比：

  • 场景1：简单过滤
  • WHERE miner_id IN (SELECT …) → 子查询更直观，性能相当
  • 场景2：需要多表字段
  • JOIN后直接SELECT多表字段 → JOIN更高效，一次查询完成
  • 场景3：相关子查询
  • WHERE EXISTS (SELECT … WHERE 外键=主键)
  • → 每行都要执行子查询，性能差
  • → 改为JOIN通常更高效
  • 场景4：MySQL 8.0 半连接优化
  • MySQL 8.0会将IN子查询优化为半连接
  • 子查询和JOIN性能差距缩小

总结

多表查询是SQL能力的核心体现。在实际场景中，我从”只会单表查询”到”熟练使用JOIN和子查询”，核心收获是：JOIN字段加索引、小表驱动大表、避免过多表关联。掌握这几点，多表查询的性能就不会差。

经过深入学习，我还理解了：

  • Nested Loop Join是MySQL默认的JOIN算法，被驱动表有索引时走Index Nested Loop
  • MySQL 8.0引入Hash Join替代Block Nested Loop，无索引JOIN性能大幅提升
  • 子查询和JOIN的选择取决于场景，简单过滤用子查询，复杂关联用JOIN
  • 递归CTE是MySQL 8.0处理层级数据的利器
  • 合理的索引设计和查询拆分是优化多表查询的关键
