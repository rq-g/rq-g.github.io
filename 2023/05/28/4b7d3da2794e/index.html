总结

索引是MySQL优化的核心。2023年深入B+树底层后，核心认知是：索引的本质是一种有序数据结构，理解了B+树的排序规则，就能推导出最左前缀原则、索引失效场景、覆盖索引原理*不再死记硬背索引规则，而是从底层原理出发分析问题。

在实际工作中，索引设计需要权衡查询性能和写入性能，通过EXPLAIN分析、监控索引使用情况、定期维护索引，才能构建高效的数据库系统。

总结

索引是MySQL性能优化的核心，实际项目的实践总结：

  1. 理解B+树原理 — 3层存4千万行，回表是性能杀手
  2. 覆盖索引优先 — 查询列在索引中就不需要回表
  3. 联合索引精心设计 — 区分度高在前、等值在前范围在后
  4. 索引下推利用好 — MySQL 5.6+自动优化，减少回表次数
  5. 索引不是越多越好 — 5个以内、列数不超过5、区分度够高
  6. 定期监控索引使用率 — 删除无用索引、整理碎片
  7. 大表变更用工具 — pt-osc/gh-ost避免锁表
  8. MySQL 8.0新特性 — 函数索引、降序索引、隐藏列
