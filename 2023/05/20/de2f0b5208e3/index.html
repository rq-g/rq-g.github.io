并发容器对比——CopyOnWriteArrayList与ConcurrentHashMap

发布于 2023-05-20 分类：技术, 2023, 并发编程 👁

前言

在实际场景中，多线程环境下使用ArrayList和HashMap导致数据不一致——设备状态列表并发修改报ConcurrentModificationException，传感器配置Map在并发读写时数据丢失。换成ConcurrentHashMap后问题解决，但CopyOnWriteArrayList在设备列表遍历时又出现性能问题。2023年系统学习并发容器后，终于能根据矿山业务场景选择合适的容器。

线程安全容器演进

线程安全容器演进历程：

第一代：全表锁：

  • Vector / Hashtable → 每个操作都synchronized，性能极差
  • 第二代：包装类
  • Collections.synchronizedXxx → 包装类，仍然全表锁
  • 第三代：分段锁/CAS
  • ConcurrentHashMap → 分段锁(JDK7)/CAS+synchronized(JDK8)
  • CopyOnWriteArrayList → 写时复制，读无锁
  • ConcurrentLinkedQueue → 无锁CAS队列
  • 第四代：特殊场景容器
  • BlockingQueue → 阻塞队列（生产者-消费者）
  • ConcurrentSkipListMap → 跳表（有序并发Map）
  • LongAdder → 分散计数（高并发计数器）

ConcurrentHashMap扩容机制

架构流程：

红黑树转换阈值

ConcurrentHashMap 链表→红黑树转换：

TREEIFY_THRESHOLD = 8 链表长度>=8时尝试树化：

  • UNTREEIFY_THRESHOLD = 6 红黑树节点<=6时反树化为链表
  • MIN_TREEIFY_CAPACITY = 64 数组长度<64时优先扩容而非树化
  • 为什么是8？
  • 链表长度8的概率极低(约千万分之一，泊松分布)
  • 如果真的到了8，说明hash冲突严重，应该树化优化查找
  • 红黑树查找O(log n) vs 链表查找O(n)
  • 转换流程：
  • putVal() → binCount >= TREEIFY_THRESHOLD - 1
  • → treeifyBin()
  • → if (tab.length < MIN_TREEIFY_CAPACITY) resize()
  • → else 链表转红黑树
  • 实际项目：
  • 设备ID hash分布均匀，一般不会触发树化
  • 如果频繁树化 → 检查hashCode实现是否合理

面试高频问题

1. ConcurrentHashMap和Hashtable的区别？

ConcurrentHashMap用CAS+synchronized锁单个桶，并发度高；Hashtable用synchronized锁整个对象，并发度低。

2. ConcurrentHashMap JDK7和JDK8的区别？

JDK7用Segment分段锁，并发度固定为16；JDK8用CAS+synchronized锁单个桶，并发度等于数组长度，且引入红黑树优化长链表查询。

3. CopyOnWriteArrayList的原理？

写操作加锁复制整个数组，读操作无锁。适合读多写少场景，写操作O(n)性能差。

4. BlockingQueue的阻塞方法？

put/take：阻塞等待；offer/poll：非阻塞或带超时。

5. 为什么ConcurrentHashMap不允许null key/value？

因为get()返回null时无法区分是key不存在还是value为null。多线程场景下如果允许null，containsKey()+get()复合操作会有歧义。

6. ConcurrentHashMap的扩容机制？

多线程协助扩容，每个线程负责16个桶的迁移。迁移中的桶放ForwardingNode(hash=MOVED)，其他线程put时发现MOVED会帮忙迁移。扩容时2倍增长，链表长度>=8但数组<64时优先扩容而非树化。

7. CopyOnWriteArrayList的迭代器有什么特点？

弱一致性迭代器，创建时保存数组快照，后续修改不影响迭代。不支持remove/set/add操作（抛UnsupportedOperationException）。适合遍历远多于修改的场景。

8. LongAdder和AtomicLong的区别？

AtomicLong所有线程CAS竞争单个value，高并发下性能差。LongAdder通过Cell数组分散热点，不同线程CAS不同Cell，高并发下性能好。但LongAdder的sum()不是原子操作。

9. ConcurrentSkipListMap的特点？

基于跳表实现的有序并发Map，查找/插入/删除都是O(log n)。支持范围查询(subMap/headMap/tailMap)，CAS无锁实现，不允许null key/value。适用于需要排序和范围查询的并发场景。

10. ConcurrentHashMap中链表转红黑树的阈值为什么是8？

泊松分布在负载因子0.75时，链表长度达到8的概率约为千万分之一。如果真的到了8说明hash冲突严重，应该树化优化。而6是反树化阈值，8和6之间留2的缓冲避免频繁转换。

总结

并发容器是JUC包的核心组件，也是实际项目中多线程编程的基础。核心认知是：ConcurrentHashMap是高并发Map的首选，CopyOnWriteArrayList只适合读多写少，BlockingQueue是生产者-消费者的最佳实现。选对容器，多线程编程事半功倍。在实际场景中，正是基于对并发容器的深入理解，我们才能在设备状态缓存、任务队列、告警处理等场景中选对容器、避坑排雷。
