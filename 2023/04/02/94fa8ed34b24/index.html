RabbitMQ实战——消息可靠投递与消费的全链路方案

发布于 2023-04-02 分类：技术, 2023, 消息队列 👁

前言

实际项目引入RabbitMQ做异步解耦后，遇到了消息丢失、重复消费、消息堆积等问题。最初只知道简单的send/receive，出了问题完全不知道怎么排查。2023年系统学习RabbitMQ后，终于搞透了消息可靠投递的全链路方案。

实际项目是一个大型工业物联网平台，包含设备数据采集、安全监控预警、生产调度管理等核心模块。系统每天需要处理百万级设备消息，涉及瓦斯监测数据上报、人员定位信息同步、设备告警事件推送等关键业务。RabbitMQ作为消息中枢，承载着整个矿山的异步通信任务，一旦消息丢失或延迟，可能直接影响矿工安全。

面试高频问题

1. 如何保证消息不丢失

2. 如何保证消息不重复消费

唯一ID + 去重表 / 业务状态机 / Redis SETNX。智慧矿山瓦斯告警使用双层去重（Redis + 数据库）。

3. RabbitMQ如何实现延迟队列

TTL + 死信队列，或使用rabbitmq_delayed_message_exchange插件。

4. 消息堆积如何处理

临时扩容消费者 + 增大prefetch + 批量消费 + 惰性队列。

5. 如何保证消息的顺序性

单消费者 + 顺序队列，或使用MessageGroupId实现分区有序。
