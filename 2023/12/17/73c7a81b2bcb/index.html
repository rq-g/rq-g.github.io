Redis实战——分布式限流方案

发布于 2023-12-17 分类：技术, 2023, Redis 👁

前言

实际项目大促期间，设备数据查询接口被频繁调用，数据库CPU打到100%，监控系统几乎瘫痪。最初在Nginx层做了简单的IP限流，但无法按用户维度限流，也无法针对不同接口设置不同策略。2023年用Redis实现了完整的分布式限流体系：从固定窗口到滑动窗口再到令牌桶，配合注解+AOP实现声明式限流，在网关层和应用层双重保障。本文系统地总结分布式限流在实际项目中的设计与实现。

Redis INCR 命令源码分析：

  • INCR命令执行流程：
    1. 查找key对应的robj对象
    1. 检查对象类型是否为OBJ_STRING
    1. 检查编码是否为OBJ_ENCODING_INT
    1. 将值转为long long类型
    1. 执行++操作
    1. 写入新值
  • 关键源码（t_string.c）：
  • void incrCommand(client *c) {
  • long long value;
  • robj *o;
  • o = lookupKeyWrite(c->db, c->argv[1]);
  • if (getLongLongFromObject(o, &value) != C_OK)
  • addReplyError(c, “value is not an integer”);
  • value++;
  • o = createObject(OBJ_STRING, cs);
  • dbOverwrite(c->db, c->argv[1], o);
  • }
  • 为什么INCR是原子的？
  • Redis单线程执行命令，INCR执行期间不会被其他命令打断
  • 即使多个客户端同时INCR，也是串行执行

面试高频问题

1. 分布式限流有哪些算法？

固定窗口（简单但有临界问题）、滑动窗口（平滑无临界）、漏桶（恒定速率处理）、令牌桶（允许合理突发）。实际项目推荐令牌桶做API限流，滑动窗口做精确限流，固定窗口只用于粗粒度场景。

2. 滑动窗口怎么实现？

用ZSet存储每次请求的时间戳，member=请求ID:时间戳，score=时间戳。ZREMRANGEBYSCORE清除窗口外数据，ZCARD统计窗口内请求数。Lua脚本保证三步操作原子性。

3. 令牌桶和漏桶的区别？

令牌桶允许突发流量（桶里有令牌就可以立即处理），漏桶恒定速率处理（不管来多少请求都以固定速率输出）。API限流用令牌桶（允许短时突发），流量整形用漏桶（匀速输出）。智慧矿山中设备查询API用令牌桶，数据同步用漏桶。

4. 为什么用Lua脚本？

Redis执行Lua脚本是原子的，不会被其他命令打断。INCR+EXPIRE、ZREM+ZCARD+ZADD等非原子操作在并发下会出现计数不准，Lua脚本可以合并为原子操作。

5. 分布式限流如何保证多实例一致？

使用Redis作为集中存储，所有实例共享Redis中的限流计数器。无论请求落到哪个实例，都读写同一个Redis key，从而保证限流效果一致。

6. 限流被拒后怎么处理？

返回429状态码+友好提示信息，不要直接返回500。实际项目中自定义RateLimitException，全局异常处理器捕获后返回Result.fail(429, “操作过于频繁”)。同时记录限流日志，方便后续分析。

7. 网关层限流和应用层限流怎么配合？

网关层粗粒度限流（按IP，高阈值），防止恶意攻击；应用层细粒度限流（按IP/用户/接口，精确阈值），防止业务过载。网关层限流值应大于应用层限流值，两层互不冲突。

8. 令牌桶冷启动问题怎么解决？

服务启动时令牌桶满载，突发流量可全部通过。解决方案：初始令牌数设为maxTokens*0.1，或使用渐进式预热策略，根据服务运行时间逐步增加可用令牌数。
