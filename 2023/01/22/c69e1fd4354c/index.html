Spring AOP动态代理实现——JDK与CGLIB的抉择

发布于 2023-01-22 分类：技术, 2023, Spring源码 👁

前言

2022年学会了AOP的基本使用，但一直没搞明白：Spring AOP底层是怎么把一个普通对象变成代理对象的？JDK动态代理和CGLIB有什么区别？为什么有时候AOP会失效？

在实际场景中，在为设备监控模块添加AOP切面时，遇到了代理失效导致事务不回滚的线上事故。这次事故让我意识到必须深入AOP底层源码，彻底理解JDK与CGLIB的抉择机制。

实际项目是一个大型工业物联网平台，包含设备监控、安全预警、人员定位、生产调度等核心模块。项目技术栈：SpringBoot 2.7 + SpringCloud + Nacos + MyBatis-Plus + Redis + MQTT + 时序数据库。整个系统需要处理上千个矿井传感器的实时数据，AOP被广泛应用于操作日志、权限校验、耗时监控、事务管理等横切关注点。

深入源码后，JDK与CGLIB的抉择、代理创建时机、AOP失效场景等问题全部有了答案。

本文还包含接口限流、分布式锁等AOP实战案例，以及日志存储设计和项目切面架构总览，从理论到源码再到工程实践，全面覆盖AOP的核心知识。

代理模式回顾

代理模式的核心思想：不修改原对象，通过代理对象增强功能。在实际场景中，我们通过代理为设备操作方法统一添加日志记录、权限校验和耗时统计。

项目切面架构总览

实际项目中的所有AOP切面按优先级组织如下：

切面 功能 切入点 优先级
AuthAspect 权限校验 @RequirePermission @Order(1)

切面执行顺序说明：

  • @Order(1) 权限校验最优先，无权限直接拒绝，避免后续无意义的处理
  • @Order(2) 限流在权限之后，防止无权限的请求也消耗限流配额
  • @Order(3) 操作日志记录完整的操作过程
  • @Order(4) 数据权限在返回结果后过滤数据
  • @Order(5) 分布式锁仅在需要互斥的场景生效

面试高频问题

1. JDK和CGLIB的区别？

JDK基于接口，只能代理接口方法；CGLIB基于继承，可以代理非final的public方法。SpringBoot 2.x默认使用CGLIB（proxy-target-class=true）。JDK代理创建快但调用慢（反射），CGLIB创建慢但调用快（FastClass索引）。

2. Spring AOP的代理创建时机？

在Bean初始化的最后阶段（BeanPostProcessor#postProcessAfterInitialization），如果Bean匹配任何Advisor，就创建代理对象替换原Bean。如果发生循环依赖，代理可能在实例化后提前创建（通过SmartInstantiationAwareBeanPostProcessor#getEarlyBeanReference）。

3. 为什么同类调用AOP会失效？

因为内部调用走的是this引用（目标对象本身），而不是代理对象。解决方案：注入自身代理（@Autowired @Lazy）、AopContext.currentProxy()（需exposeProxy=true）、从ApplicationContext获取代理对象。

4. SpringBoot 2.x为什么默认用CGLIB？

因为实际开发中很多类没有接口（如直接在类上加@Service），JDK代理无法处理。CGLIB不依赖接口，适用范围更广。proxy-target-class默认为true，统一使用CGLIB避免混淆。

5. CGLIB的FastClass机制是什么？

CGLIB生成代理类时，同时生成两个FastClass类（分别对应代理类和目标类）。FastClass为每个方法分配一个index，调用时通过index直接定位方法，跳过反射。这比JDK的method.invoke()性能更好。

总结

深入AOP动态代理源码后，我理解了三个核心机制：JDK基于接口代理、CGLIB基于继承代理、Spring在BeanPostProcessor阶段创建代理。最实用的收获是彻底搞懂了AOP失效的各种场景——本质上都是”没有通过代理对象调用方法”导致的。

在实际场景中，AOP被广泛应用于设备操作日志、权限校验、耗时监控、事务管理等横切关注点。理解了代理原理后，遇到AOP失效问题能快速定位：先判断是否走了代理对象，再检查方法修饰符、异常处理、事务传播行为等具体原因。
