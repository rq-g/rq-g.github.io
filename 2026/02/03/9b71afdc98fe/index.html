SpringCloud Alibaba微服务面试题——Nacos、Sentinel、Gateway、Feign

前言

微服务架构是大型互联网公司的标配，SpringCloud Alibaba是国内最流行的微服务框架。但只背面试题不够，面试官追问项目实战就会露馅。这篇文章结合微服务核心原理、项目实战经验，从源码层面深入分析Nacos、Sentinel、Gateway、Feign的核心原理，全面覆盖面试高频考点。

一、Nacos服务注册发现原理

1. Nacos架构

层级 组件 说明
Nacos Server 注册中心 内存注册表 + MySQL持久化
配置中心 动态配置管理
集群管理 Raft选举 + Distro协议
心跳检测 临时实例5秒心跳，永久实例主动探测
Nacos Client 服务注册 启动时向Server发送注册请求
服务发现 订阅服务列表，UDP推送变更
配置订阅 长轮询监听配置变更
心跳保活 临时实例定期发送心跳

2. 服务注册流程（源码级）

临时实例 vs 持久实例：

维度 临时实例（ephemeral=true） 持久实例（ephemeral=false）
注册方式 客户端主动注册 服务端主动探测
心跳机制 客户端发送心跳 服务端主动探测
不健康处理 超时剔除 仅标记不健康，不剔除
一致性 AP（Distro协议） CP（Raft协议）
适用场景 微服务实例 数据库、中间件

3. 服务发现流程

Nacos服务发现两种模式：

模式 说明 特点
Pull模式 客户端定时从Server拉取服务列表 实时性差，减轻Server压力
Push模式 Server通过UDP推送服务变更 实时性好，UDP可能丢失
★ 实际 Pull + Push结合 定时Pull兜底 + UDP Push实时通知

4. CAP理论下的Nacos

模式 CAP特性 说明 适用场景
AP模式 可用性 + 分区容错 优先保证服务可用，最终一致性 ★ 微服务注册（默认）
CP模式 一致性 + 分区容错 优先保证数据一致，牺牲可用性 持久化实例

5. Nacos集群部署

集群要点：

  • 至少3个节点，保证多数派选举
  • 使用MySQL作为持久化存储（内嵌Derby无法集群共享）
  • 前置Nginx做负载均衡和VIP
  • 临时实例使用Distro协议（AP），持久实例使用Raft协议（CP）

二、Sentinel限流、熔断、降级

1. 三者区别

维度 限流 熔断 降级
目的 控制流量入口 保护下游服务 保护核心服务
触发条件 QPS/并发数达到阈值 异常比例/慢调用达到阈值 主动降级非核心服务
处理方式 拒绝请求（BlockException） 熔断一段时间 返回降级数据
恢复方式 自动恢复 熔断后自动尝试恢复 人工恢复
类比 地铁限流进站 保险丝熔断 舱壁抛弃货物

Rule 保护规则（限流、熔断、降级）
Slot Chain 处理链（统计→规则检查→执行）
Entry 资源访问入口

3. 限流配置

限流效果对比：

效果 说明 适用场景
直接拒绝 超过阈值直接抛出BlockException 适合前端限流
冷启动 QPS缓慢提升到阈值 适合系统冷启动
匀速排队 请求匀速通过，多余排队 适合削峰填谷

4. 熔断配置

熔断策略对比：

策略 说明 适用场景
慢调用比例 RT超过阈值的请求比例触发熔断 下游服务响应慢
异常比例 异常比例超过阈值触发熔断 下游服务不稳定
异常数 异常数量超过阈值触发熔断 下游服务偶尔失败

熔断恢复机制（三状态转换）：

  • 关闭：正常放行请求，统计异常数据
  • 打开：所有请求直接拒绝，调用fallback
  • 半开：经过timeWindow后放行一个请求探测，成功则关闭，失败则继续打开

5. 降级配置

blockHandler vs fallback：

维度 blockHandler fallback
触发条件 限流/熔断/系统保护（BlockException） 业务异常（Throwable）
方法签名 原方法参数 + BlockException 原方法参数 + Throwable
优先级 高（限流优先于降级） 低

五、微服务场景题

1. 服务宕机容错方案

序号 方案 组件 说明
1 熔断降级 Sentinel 检测异常比例，超过阈值熔断，返回降级数据
2 服务隔离 Sentinel线程池隔离 每个服务独立线程池，避免一个服务耗尽所有线程
3 限流 Gateway/Sentinel 限制入口流量，保护后端服务
4 服务发现剔除 Nacos 心跳检测剔除不健康实例，避免请求发送到宕机服务
5 熔断后恢复 Sentinel 熔断后自动尝试恢复，半开状态测试服务可用性
6 超时重试 Feign 配置合理的超时和重试策略
7 缓存降级 Redis 非核心服务降级时从缓存获取数据

2. 调用链过长优化

调用链优化方法对比：

方法 说明 效果
并行调用 CompletableFuture并行请求 串行→并行，耗时取最大值
API聚合层 网关层聚合多个接口 减少前端请求次数
数据冗余 冗余常用字段，减少跨服务调用 牺牲一致性换性能
GraphQL 客户端按需查询字段 减少不必要的数据传输

六、真实项目中的常见问题

问题 原因 解决方法
Nacos服务注册延迟 服务启动后，其他服务无法立即发现 缩短心跳间隔、配置健康检查延迟
Nacos配置中心连接失败 Nacos宕机后应用启动失败 配置本地缓存（failfast=false）、启动重试
Sentinel规则丢失 Dashboard配置的规则重启后丢失 配置Nacos持久化（推模式）
Sentinel熔断不生效 资源名不匹配 确保@SentinelResource的value与规则资源名一致
Sentinel降级方法找不到 blockHandler方法签名不正确 blockHandler必须和原方法同参数+BlockException
Gateway跨域问题 前端请求被CORS拦截 配置globalcors或CorsWebFilter
Gateway请求体丢失 全局过滤器中读取body后下游服务获取不到 使用DataBuffer缓存body，重新包装ServerHttpRequest
Gateway路由优先级冲突 多个路由规则匹配同一请求 更具体的规则放前面，按声明顺序匹配
Feign超时配置不生效 同时配置了Ribbon和Feign的超时 Feign优先级高于Ribbon，移除Ribbon超时配置
Feign丢失请求头 异步线程中RequestContextHolder为null 手动传递Header或使用RequestInterceptor
Feign重试导致重复操作 非幂等接口重试导致数据重复 非幂等接口关闭重试，使用唯一请求ID
Feign调用返回404 服务名拼错或路径不匹配 检查@FeignClient的name和@GetMapping路径
Nacos命名空间隔离不生效 未配置namespace或配置错误 确保Provider和Consumer的namespace一致
Sentinel热点参数限流失效 参数索引配置错误 参数索引从0开始，确保类型一致
服务上下线瞬间请求失败 Nacos实例下线后客户端缓存未更新 缩短心跳超时、使用平滑下线（先从Nacos注销再停服）

七、最佳实践

1. Nacos最佳实践

实践 说明
环境隔离 使用namespace区分dev/test/prod
服务分组 使用group区分不同业务线
集群部署 至少3节点+MySQL持久化
配置格式 使用yaml格式，便于管理
配置加密 敏感配置使用加密存储

2. Sentinel最佳实践

实践 说明
规则持久化 配置Nacos数据源，避免规则丢失
资源名规范 使用接口名:方法名格式
降级优先 先降级非核心服务，保护核心服务
合理阈值 根据压测数据设置限流阈值
监控告警 Dashboard监控+钉钉/企微告警

3. Gateway最佳实践

实践 说明
过滤器顺序 日志→认证→限流→路由
超时配置 根据下游服务响应时间调整
跨域配置 使用globalcors统一配置
灰度发布 使用Weight路由断言
限流配置 使用RequestRateLimiter + Redis

4. Feign最佳实践

实践 说明
使用fallbackFactory 可感知异常原因，便于日志记录
传递请求头 使用RequestInterceptor传递认证信息
超时配置 按服务配置不同超时时间
关闭非幂等重试 POST/PUT接口不重试
开启压缩 减少网络传输量

总结

SpringCloud Alibaba是微服务架构的核心框架，掌握这些知识不仅能应对面试，还能设计出高可用的微服务系统。核心要点：
