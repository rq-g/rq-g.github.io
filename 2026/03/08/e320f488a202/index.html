一、ArrayList 和 LinkedList 的区别

ArrayList：动态数组

LinkedList：双向链表

2. 核心区别对比

维度 ArrayList LinkedList

缓存命中 高（数组连续内存） 低（链表节点分散）
实现接口 List、RandomAccess List、Deque

5. 业务场景选择

场景 选择 理由
主要是查询 ArrayList 随机访问O(1)，缓存友好

二、HashMap 底层结构

1. JDK1.7 vs JDK1.8

维度 JDK1.7 JDK1.8
数据结构 数组 + 链表 数组 + 链表 + 红黑树
插入方式 头插法 尾插法
扩容迁移 重新计算hash定位 高低位拆分（原位置或原位置+旧容量）
hash计算 9次扰动 2次扰动（异或高16位）
死循环问题 有（并发扩容时链表成环） 无（尾插法不会成环，但仍非线程安全）
节点类型 Entry Node / TreeNode

2. JDK1.8 数据结构

JDK1.8 HashMap数据结构

槽位 数据类型 说明
0 null 空槽位
1 Node（链表） 链表长度 < 8
2 null 空槽位
3 TreeNode（红黑树） 链表长度 ≥ 8 且数组长度 ≥ 64 时转换

红黑树转换条件：

  • 链表 → 红黑树：链表长度 ≥ 8 且数组长度 ≥ 64
  • 红黑树 → 链表：红黑树节点数 ≤ 6

为什么是8？根据泊松分布，链表长度达到8的概率仅为0.00000006，属于极端情况。

扩容示例（容量从16扩到32）：

key hash 旧位置 (n=16) hash & oldCap 新位置 (n=32)
A 15 15 0 15（不变）
B 31 15 16 31（15+16）
C 7 7 0 7（不变）
D 23 7 16 23（7+16）

为什么容量必须是2的幂：

  • (n - 1) & hash 等价于 hash % n，但位运算更快
  • 保证 (n - 1) & hash 的结果均匀分布
  • 扩容时元素迁移更高效（只需判断高位是0还是1）

3. ConcurrentHashMap 原理（JDK1.8）

维度 JDK1.7 JDK1.8
数据结构 Segment[] + HashEntry[] Node[] + 链表 + 红黑树
锁粒度 Segment段锁（默认16段） 桶节点锁（synchronized）
并发度 默认16 等于数组长度
查询复杂度 O(n)遍历链表 O(log n)红黑树

JDK1.8 ConcurrentHashMap核心机制：

  • CAS + synchronized 保证线程安全
  • 锁粒度：锁桶头节点（Node），不锁整个数组
  • put流程：
    1. 计算hash，定位桶
    2. 桶为空 → CAS写入
    3. 桶不为空 → synchronized锁住头节点，再插入
    4. 链表长度 ≥ 8 → 转红黑树
  • size统计：baseCount + CounterCell[]，无锁累加

四、HashSet 底层原理

1. 底层就是 HashMap

核心原理：

  • HashSet的元素作为HashMap的key
  • value是一个固定的Object对象（PRESENT）
  • add返回true表示元素不存在且插入成功，false表示元素已存在

2. 如何保证元素不重复

结论：HashSet保证元素不重复，依赖于元素的equals和hashCode方法。

3. equals和hashCode的契约

为什么必须同时重写equals和hashCode：

  • 只重写equals：两个equals为true的对象可能hash不同，分到不同桶，HashSet判断不出重复
  • 只重写hashCode：hash相同但equals为false，会形成链表，仍无法去重
  • 必须同时重写，且保证：equals为true的对象，hashCode必须相同

2. HashMap 可以用 null 作为 key 吗？

可以。HashMap允许一个null key，放在index=0的位置。

注意：ConcurrentHashMap不允许null key和null value，因为并发场景下get返回null无法区分”key不存在”还是”value为null”。

3. HashSet 怎么保证有序？

HashSet无序。如果需要有序，用：

  • LinkedHashSet：保证插入顺序（底层是LinkedHashMap）
  • TreeSet：保证自然顺序或自定义排序（底层是TreeMap红黑树）

5. HashMap的key可以是可变对象吗？

不建议。如果key对象在放入HashMap后被修改，导致hashCode变化，将无法正确get。

最佳实践：HashMap的key使用不可变对象（如String、Integer）。

六、最佳实践

集合 适用场景 注意事项
ArrayList 随机查询、尾部插入 指定初始容量避免扩容
LinkedList 队列/双端队列、头部插入 尽量少用随机访问
HashMap 键值对存储 重写key的equals和hashCode
ConcurrentHashMap 并发场景 不能用null key/value
HashSet 去重 元素要重写equals和hashCode
LinkedHashSet 去重 + 保持插入顺序 内存比HashSet略大
TreeSet 去重 + 排序 元素实现Comparable或传入Comparator

总结

集合是Java开发的基本功，面试时要做到：

  1. ArrayList/LinkedList：能说出底层结构和效率对比，理解CPU缓存对性能的影响
  2. HashMap：能讲清楚JDK1.7→1.8的区别、put流程、扩容机制、为什么容量是2的幂
  3. HashSet：知道底层是HashMap，以及为什么要同时重写equals和hashCode
  4. 线程安全：知道HashMap为什么不安全，ConcurrentHashMap的锁机制演进
