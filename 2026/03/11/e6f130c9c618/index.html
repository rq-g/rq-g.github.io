一、分布式事务（项目实战重点）

1. CAP定理（面试必备）

特性 英文 说明
一致性 Consistency 数据一致
可用性 Availability 服务可用
分区容错 Partition 分区容错

分布式系统只能满足其中两项：

组合 说明 适用场景
CA 放弃分区容错 不实际
CP 优先保证一致性 Redis/Zookeeper/Nacos CP模式
AP 优先保证可用性 Eureka/Nacos AP模式

2. BASE理论（面试必备）

特性 英文 说明
基本可用 Basically Available 基本可靠
软状态 Soft state 允许状态变化
最终一致性 Eventually consistent 最终一致
一致性类型 说明 适用场景
强一致性 数据实时一致 金融交易、库存扣减
最终一致性 数据最终一致 日志收集、数据同步

3. 分布式事务方案对比（面试必备）

方案 原理 优点 缺点 适用场景
XA 两阶段提交 强一致性 性能差、阻塞 数据库层面事务
Seata AT 自动回滚 简单易用 性能中等 微服务
TCC Try-Confirm-Cancel 性能高 实现复杂 高并发
SAGA 状态机补偿 灵活 实现复杂 长流程
本地消息表 消息异步补偿 简单 侵入性大 最终一致性

二、分布式ID（项目实战）

1. 分布式ID要求（面试必备）

要求 说明
全局唯一 多个服务生成的ID不能重复
趋势递增 ID随时间递增，有利于索引
高可用 ID生成服务不能宕机
高性能 ID生成速度要快
可反解 可以从ID中获取时间、业务信息

2. 分布式ID方案对比（面试必备）

方案 优点 缺点 适用场景
UUID 简单、无中心 无序、占用空间大 非主键场景
数据库自增 有序、简单 单点、性能瓶颈 中小规模
Redis自增 高性能、有序 依赖Redis 高并发
雪花算法 高性能、有序、可反解 时钟回拨 大规模分布式
百度UidGenerator 趋势递增 依赖时间 高并发
美团Leaf 高可靠 实现复杂 大规模

3. 雪花算法实现（实际项目实战）

4. 雪花算法踩坑记录

问题 现象 解决方法
时钟回拨 服务器时间回拨，导致ID重复 等待时间追上、使用历史时间、拒绝服务
workerId分配 多个服务使用相同workerId 使用配置中心（Nacos/Apollo）统一分配
Long类型溢出 ID超过Long.MAX_VALUE 使用64位ID，注意位运算溢出

三、分布式锁（项目实战）

1. 分布式锁要求（面试必备）

要求 说明
互斥性 同一时刻只能有一个客户端持有锁
可重入 同一客户端可以多次获取锁
锁超时 锁要能自动过期，防止死锁
高可用 锁服务不能宕机
公平性 按请求顺序获取锁（可选）

2. 分布式锁方案对比（面试必备）

方案 优点 缺点 适用场景
Redis SETNX 性能高 不可重入 短时锁
Redis Redisson 可重入、自动续期 依赖Redis 通用
Zookeeper 强一致、可重入 性能较低 分布式协调
etcd 高可用、强一致 性能较低 分布式协调

3. Redis分布式锁（实际项目实战）

项目背景

  • 车辆控制需要互斥：同一时间只能执行一个控制命令
  • 设备操作需要原子性：不能出现并发操作
  • 锁超时需要自动续期

项目数据

  • 日均加锁次数：100000+
  • 锁竞争比例：10%
  • 锁获取成功率：99.9%

4. 分布式锁踩坑记录

问题 现象 解决方法
锁自动续期 锁过期了，业务还在执行 Redisson看门狗机制，自动续期
锁释放时机 在finally中释放锁，但锁已过期 检查锁是否由当前线程持有
锁粒度 锁粒度太大，导致并发能力下降 按业务拆分锁（按deviceId加锁）
锁超时设置 锁超时设置太短，业务执行不完 根据业务执行时间设置超时时间
