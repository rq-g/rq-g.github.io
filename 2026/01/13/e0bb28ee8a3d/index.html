一、事务四大特性ACID

1.1 ACID详解

特性 全称 说明 实现机制
Atomicity 原子性 事务是不可分割的工作单元，要么全部执行，要么全部不执行 Undo Log + 回滚机制
Consistency 一致性 事务执行前后，数据库的完整性约束没有被破坏 约束检查 + AID三大特性共同保证
Isolation 隔离性 多个事务并发执行时，彼此之间不能互相干扰 锁机制 + MVCC
Durability 持久性 事务一旦提交，对数据库的修改就是永久性的 Redo Log + WAL机制

二、MySQL四种事务隔离级别

2.1 隔离级别对比

隔离级别 脏读 不可重复读 幻读 说明 适用场景
READ UNCOMMITTED 可能 可能 可能 最低级别 极少使用

并发问题详解：

问题 描述 示例
脏读 读取到其他事务未提交的数据 事务A修改数据未提交→事务B读到→事务A回滚→事务B读到脏数据
不可重复读 同一事务内两次查询同一数据，结果不一致 事务A查balance=100→事务B修改为200并提交→事务A再查balance=200
幻读 同一事务内两次查询，行数不一致 事务A查status=1有10行→事务B插入1行status=1→事务A再查有11行

三、索引原理与优化

3.1 索引类型对比

类型 说明 特点 使用场景
主键索引 PRIMARY KEY 唯一、非空、聚簇索引 主键查询、表连接
唯一索引 UNIQUE KEY 唯一、可空 唯一约束场景
普通索引 INDEX / KEY 可重复、可空 普通查询
复合索引 多个字段组合 遵循最左前缀原则 多条件查询
全文索引 FULLTEXT 文本搜索 全文检索
前缀索引 字段前N个字符 减少索引大小 长字符串字段

主键索引 vs 普通索引：

维度 主键索引 普通索引
唯一性 必须唯一且不为空 可以重复
数量限制 一个表只能有一个 可以有多个
存储结构 聚簇索引（InnoDB） 非聚簇索引
查询效率 最高（直接定位数据） 次高（需要回表）

3.2 B+树索引结构

InnoDB聚簇索引结构：

层级 节点类型 存储内容
第1层 根节点 [100, 200] 索引键+子节点指针
第2层 非叶子节点 [50,75], [150,175] 索引键+子节点指针
第3层 叶子节点 完整数据行 + 双向链表指针

B+树 vs B树 vs Hash索引：

特性 B+树 B树 Hash索引
查询类型 精确+范围 精确+范围 仅精确查询
查询效率 O(logn) O(logn) O(1)
范围查询 支持（叶子链表） 支持（复杂度高） 不支持
查询稳定性 稳定（必须到叶子） 不稳定 稳定
磁盘IO 少（树高低） 多（树高高） 少
排序 支持 支持 不支持
适用场景 ★ 数据库索引 少用 Memory引擎/等值查询

为什么MySQL选择B+树？

  1. 非叶子节点只存索引键，容纳更多键，降低树高，减少磁盘IO
  2. 叶子节点双向链表，范围查询只需遍历链表
  3. 所有查询必须到叶子节点，查询时间稳定
  4. 顺序访问时缓存命中率高

3.4 最左前缀原则

联合索引设计原则：

原则 说明 示例
区分度高的字段在前 过滤效果更好 name区分度 > gender
WHERE字段在前，ORDER BY在后 避免filesort (status, created_at)

3.5 索引失效场景

场景 示例 优化方案
索引列使用函数 WHERE DATE(created_at) = '2024-01-01' WHERE created_at >= '2024-01-01' AND created_at < '2024-01-02'
索引列参与计算 WHERE age + 1 = 20 WHERE age = 19
类型不匹配 WHERE name = 123（name是VARCHAR） WHERE name = '123'
左模糊查询 WHERE name LIKE '%张三' 全文索引或ES
OR条件无索引端 WHERE a=1 OR b=2（b无索引） 拆分为UNION
隐式编码转换 utf8和utf8mb4关联 统一字符编码
NOT IN WHERE id NOT IN (1,2,3) 改为NOT EXISTS
优化器判断全表更快 数据量小或查询比例高 正常行为，无需处理

3.6 索引使用建议

建议 说明
优先使用主键查询 主键查询效率最高，不需要回表
避免SELECT * 只查询需要的字段，可能触发覆盖索引
复合索引顺序 区分度高的字段放前面，遵循最左前缀原则
索引数量适中 索引过多会影响写入性能（建议单表5-8个）
使用EXPLAIN分析 查看执行计划，确认索引是否命中
定期清理冗余索引 使用SHOW INDEX FROM table检查

八、真实项目中的MySQL问题

问题 原因 解决方案
慢查询突增 新上线SQL缺少索引 EXPLAIN分析+添加索引
索引失效 隐式类型转换/函数/左模糊 避免运算、统一类型
死锁频发 事务获取锁顺序不一致 按固定顺序操作、缩短事务
行锁升级为表锁 UPDATE/DELETE未走索引 确保WHERE条件有索引
主从延迟 从库SQL线程单线程重放慢 并行复制、分库降低压力
深分页慢查询 LIMIT 1000000,10扫描太多行 延迟关联/游标分页
Using filesort ORDER BY字段无索引 WHERE+ORDER BY建联合索引
Using temporary GROUP BY和ORDER BY不同列 统一字段或冗余列
大事务阻塞 事务中包含RPC调用 事务中只做DB操作
连接数耗尽 未关闭连接/慢查询占用 排查慢查询、配置wait_timeout
唯一索引死锁 两个事务交替插入相同唯一键 业务层保证唯一
自增ID不连续 事务回滚或MySQL重启 正常现象
Buffer Pool污染 全表扫描将热数据挤出 调大innodb_old_blocks_time
批量插入太慢 逐条INSERT + autocommit 批量INSERT + rewriteBatchedStatements
